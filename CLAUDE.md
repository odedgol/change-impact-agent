# Change Impact Agent

Portfolio project (target: Twine Security, Backend Engineer – Agentic AI). Before an IAM identity/permission is deleted or changed, an agent gathers evidence and returns a risk report (confidence + safe_to_delete / disable_first / ask_owner / insufficient_evidence). A separate reversible executor runs only after human approval.

## Design rules
- Simulate the data tools return, not the tools. One `EvidenceSource` interface (`SyntheticSource` now; `AwsSource`/`KeycloakSource` optional) and one `LLMClient` interface (`BedrockClient`, `OpenAICompatClient` for Ollama/vLLM, `OpenRouterClient`, `FakeLLM`), built through `make_client`. Keep each provider its own adapter; never replace one with another.
- Evidence tools are read-only (SQLite `mode=ro`). Guardrails live in code, not in the prompt.
- Incomplete is never safe: a failing source is a tool error, not empty data; `safe_to_delete` needs usage, dependencies and tickets read in full, else `insufficient_evidence`. Grounded, not just cited: a `safe_to_delete` its own evidence contradicts, or that does not cite those three, becomes `ask_owner`. Before acting, evidence is read fresh and compared with the snapshot (no cache). Only `safe_to_delete` permits a delete. Freshness metadata is optional and never invented.
- Agent engine: LangGraph `StateGraph` in `src/cia/graph.py`. Never a hand-written `while True` loop. LangGraph decides order only; guardrails stay plain tested functions. After changing either graph (`graph.py` or `workflow.py`) run `make graph` (redraws `docs/index.html#engine` and `#change-graph`); a new node needs a docstring and a `NODE_KIND`, a new route a `ROUTE_LABELS` entry, in the module of its graph.
- Executor: dry-run, disable-first, undo, idempotency; append-only audit log.
- AWS: only through `infra/aws/`. Nothing is created without the init plan (`make aws-plan`) approved by the user; every demo ends with the destroy plan and `make aws-check` printing 0. OpenSearch Serverless only as NextGen (scale to zero), never Classic.
- Cloud-agnostic: AWS is one deployment target, never a dependency; the design must move to a private cloud. Cloud services sit behind an interface or open protocol (`LLMClient`, `EvidenceSource`, `AuditSink`, Postgres SQL, LangGraph checkpointer, OCI containers). `boto3` is imported only inside adapter classes, and each adapter has a non-AWS sibling or a fake. Mapping: `docs/index.html#portable`.
- Intake and messages are adapters: HR events come in through `cia.service`; people hear through a `Notifier` (console, Slack, later others). The buttons come only from the guardrails' allowed actions; message text from the model is shown, never obeyed.
- Terminal UI: Rust (ratatui) in `tui/`, a separate binary that only reads the investigator's JSON-lines events; it never imports the agent.
- Stack: Python 3.12+, Pydantic v2, FastAPI, boto3 Bedrock Converse, LangGraph (investigator `StateGraph` and change workflow `StateGraph`; human approval and the quiet period via `interrupt()`; `SqliteSaver` now, Postgres checkpointer later; no LangChain models or tools), Postgres later, pytest, Ruff.
- Hard eval gates: 0 unsafe-delete recommendations, 0 unapproved actions, 0 wrong deletes (the bench runs the whole workflow). Targets (recall >= 90%, precision >= 80%) are proposals, not proven.

## Docs are HTML-first
- Plans, specs, design notes, weekly plans and results live in `docs/*.html`: self-contained single files (inline CSS/JS/SVG, light and dark theme, readable at phone width, no build step).
- Only `README.md` and `CLAUDE.md` stay Markdown (GitHub and Claude Code read them as Markdown).
- Before coding each week, write `docs/week-N.html` (plan, diagram, acceptance checks); update it when done. Keep each page short and visual; tables and diagrams over prose.
- **Every change updates the docs in the same PR (mandatory).** Before committing, find each `docs/*.html` section the change affects and update it: the week plan (step status, validation checks ticked, decisions), the hub (`docs/index.html`: sprints and PR table, roadmap status, tech stack, PR workflow gates, overview status), and the status lines in `CLAUDE.md`.
