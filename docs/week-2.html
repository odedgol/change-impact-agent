Week 2: investigator loop

Two swappable interfaces, a tool-calling loop, and a structured report where every finding cites evidence ids that code verifies.

Status
done · all steps merged (PR 2.1–2.9, plus R1): bench (0 unsafe deletes on every model run; gemma4 20/20 on Ollama and on OpenRouter), LangGraph engine, Rust UI, generated graph docs, one code style; next: week 3 · updated 2026-10-17
Delivers
investigate(request) -> RiskReport
Done when
make bench-fake prints unsafe_deletes: 0

The loop returns one verdict with a confidence: safe_to_delete disable_first ask_owner. Every finding cites ids from this run's tool log, such as ev-deps-3. It is proven end to end with FakeLLM, plus one smoke run on Bedrock.

Where this sits in the system: the request loop (steps 2–4) and the five layers (layers 2, 3 and 5).

Scope

In, week 2

  • EvidenceSource Protocol; SyntheticSource is today's EvidenceTools
  • LLMClient Protocol; FakeLLM and BedrockClient
  • Investigator: loop, step cap, dispatch, tool log, parsing
  • Pydantic models and the citation check, with one retry
  • cia.bench: agent vs ground truth

Out, week 3 and later

  • Guardrails beyond the citation check
  • Human approval (LangGraph interrupt()), executor, audit log
  • Credential chain (Q10), doc index (Q9, Q11)
  • FastAPI, Postgres, red-team cases

Assumptions: the generator and ground truth don't change, so the 7 week-1 tests stay green. Unit tests and CI never call Bedrock. Tools stay read-only.

Open questions

These are for weeks 3 and 4 and don't block week 2. Each one has a recommended answer.

Q9week 4

Index internal docs for evidence that never names the account?

Recommended: yes, as a measured experiment.

  • Hybrid search on pgvector: keywords for exact names, embeddings for paraphrases.
  • Index when a doc changes; extract candidate links; an alias table maps names to identity_id.
  • Docs are leads, not proof: a doc-only finding caps the verdict at ask_owner.
  • Measured on a new case type, doc_only_dependency, with and without the index.
Q10week 3

Model credential chains, such as a leaver's API key that a pipeline still uses?

userownsES API keystored insecretread bypipelineowned byteam

Recommended: yes, before the guardrails. A credential_chain case type (one new command in COMMANDS), four new dependency kinds, and get_dependencies following up to 4 hops, each hop logged as evidence.

Q11week 4

Should doc search widen its terms from what each round finds?

Recommended: yes, with Q9. search_docs(terms, filters, from_evidence) takes terms only from cited evidence, runs at most 4 rounds, logs each as ev-search-n; the cap rises to 12.

Validation

Each item is provable by a command or a test. CI runs make test and make lint on every PR; make bench-fake joins in PR 2.5.

  • make test passes; the 7 week-1 tests are unchanged. 136 passed after PR 2.7.
  • make lint exits 0, in CI from PR 2.1.
  • make typecheck (Pyright) reports 0 errors, in CI from PR 2.7.
  • test_models.py: empty evidence_ids and an invalid verdict both raise; also bad confidence, unknown fields, malformed evidence ids, JSON parsing and immutability (11 tests).
  • test_llm_fake.py: scripted turns come back in order, calls are recorded, an exhausted script raises (4 tests).
  • test_investigator.py (20 tests, all on FakeLLM and the real synthetic org):
    • tool calls are dispatched and logged with unique ids;
    • an unknown id is dropped and counted;
    • rejected citations trigger exactly one retry, then Q7 applies;
    • safe_to_delete with a rejection becomes ask_owner;
    • the step cap returns insufficient_evidence, never a delete;
    • an unknown tool name, bad arguments or an invalid report return a tool error, no crash;
    • list tools page with next_offset; turns without a tool call and the retry count against the cap;
    • --events writes request, tool calls and report as JSON lines.
  • test_sources.py: SyntheticSource matches EvidenceSource by name and signature; DELETE and UPDATE raise OperationalError; paging returns every row; short usage windows are clamped; consumers of owned accounts name their target (19 tests).
  • test_bedrock_mapping.py: Converse request, response, tool-result and error mapping with a stubbed client, no network or AWS (7 tests).
  • test_incomplete_and_freshness.py: old evidence and reports still validate; freshness recorded, unknown update time stays None; a missing ticket check, unread pages or a failing source turn safe_to_delete into insufficient_evidence; only safe_to_delete permits a delete (15 tests).
  • test_monitor.py: start a run over HTTP, stream its events, list it with verdict and expected verdict; a failing model shows as an error; bad request ids, model names and path traversal are rejected; the page pins React Flow and renders model output as text only (11 tests).
  • test_graph.py (6 tests): the graph has the agreed nodes and routes; coverage, finish and citation-drop rules on their own; the step cap fires before LangGraph's recursion_limit; a checkpointer saves each step under the request id. The 20 investigator tests pass unchanged on the graph.
