Week 2: investigator loop

Two swappable interfaces, a tool-calling loop, and a structured report where every finding cites evidence ids that code verifies.

Status
active · steps 1–2 merged (PR 2.1), step 3 in review (PR 2.2) · updated 2026-10-16
Delivers
investigate(request) -> RiskReport
Done when
make bench-fake prints unsafe_deletes: 0

The loop returns one verdict with a confidence: safe_to_delete disable_first ask_owner. Every finding cites ids from this run's tool log, such as ev-deps-3. It is proven end to end with FakeLLM, plus one smoke run on Bedrock.

Where this sits in the system: the request loop (steps 2–4) and the five layers (layers 2, 3 and 5).

Scope

In, week 2

  • EvidenceSource Protocol; SyntheticSource is today's EvidenceTools
  • LLMClient Protocol; FakeLLM and BedrockClient
  • Investigator: loop, step cap, dispatch, tool log, parsing
  • Pydantic models and the citation check, with one retry
  • cia.bench: agent vs ground truth

Out, week 3 and later

  • Guardrails beyond the citation check
  • Temporal approval, executor, audit log
  • Credential chain (Q10), doc index (Q9, Q11)
  • FastAPI, Postgres, red-team cases

Assumptions: the generator and ground truth don't change, so the 7 week-1 tests stay green. Unit tests and CI never call Bedrock. Tools stay read-only.

Open questions

These are for weeks 3 and 4 and don't block week 2. Each one has a recommended answer.

Q9week 4

Index internal docs for evidence that never names the account?

Recommended: yes, as a measured experiment.

  • Hybrid search on pgvector: keywords for exact names, embeddings for paraphrases.
  • Index when a doc changes; extract candidate links; an alias table maps names to identity_id.
  • Docs are leads, not proof: a doc-only finding caps the verdict at ask_owner.
  • Measured on a new case type, doc_only_dependency (one new @case_type), with and without the index.
Q10week 3

Model credential chains, such as a leaver's API key that a pipeline still uses?

userownsES API keystored insecretread bypipelineowned byteam

Recommended: yes, before the guardrails. A credential_chain case type (one new @case_type in cases.py), four new dependency kinds, and get_dependencies following up to 4 hops, each hop logged as evidence.

Q11week 4

Should doc search widen its terms from what each round finds?

Recommended: yes, with Q9. search_docs(terms, filters, from_evidence) takes terms only from cited evidence, runs at most 4 rounds, logs each as ev-search-n; the cap rises to 12.

Validation

Each item is provable by a command or a test. CI runs make test and make lint on every PR; make bench-fake joins in PR 2.5.

  • make test passes; the 7 week-1 tests are unchanged. 24 passed after PR 2.2.
  • make lint exits 0, in CI from PR 2.1.
  • test_models.py: empty evidence_ids and an invalid verdict both raise; also bad confidence, unknown fields, malformed evidence ids, JSON parsing and immutability (11 tests).
  • test_llm_fake.py: scripted turns come back in order; an empty script raises.
  • test_investigator.py:
    • tool calls are dispatched and logged with unique ids;
    • an unknown id is dropped and counted;
    • rejected citations trigger exactly one retry, then Q7 applies;
    • safe_to_delete with a rejection becomes ask_owner;
    • the step cap returns ask_owner, never a delete;
    • an unknown tool name returns a tool error, no crash.
  • test_sources.py: SyntheticSource satisfies EvidenceSource; DELETE and UPDATE raise OperationalError; caps add a truncation marker and never hide rows silently (6 tests).
  • test_bedrock_mapping.py: Converse mapping with a stubbed client, no network.
  • make bench-fake prints unsafe_deletes: 0 on the 500-identity org.
  • optionalmake bench-bedrock completes the 20 cases; result recorded here, no target claimed.
