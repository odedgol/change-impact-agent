Change Impact Agent

Before an IAM identity or permission is deleted, an agent gathers evidence and reports what could break. A separate, reversible executor acts only after a human approves.

Deleting an "unused" account is how nightly jobs, policy exceptions, shared logins and break-glass accounts break. A naive rule (no usage in 90 days → delete) breaks 6 of the 10 risky accounts in the benchmark. This project replaces that rule with an investigation whose every claim can be traced back to a tool result.

Input
A change request: identity_id and an action
Output: one verdict, with confidence

Agentic workflow

One LLM worker, not a team of agents. The steps around it are a LangGraph state graph whose nodes call small rule functions, so the order can't be talked out of, and every exit from the graph carries evidence ids that code assigned. Why LangGraph.

The request loop

Step through one request. Everything in the green zone is read-only; nothing in the red zone runs without a human.

Five layers

The standard layers of an agentic system, mapped onto this project. Edge labels are the payload that moves along each edge.

LangGraph engine

The investigator is a LangGraph StateGraph (src/cia/graph.py), not a while True loop. The model only proposes; each node calls a small rule function that is tested on its own. The drawing below is that graph: make graph writes the nodes, routes and each node's docstring from the compiled graph into this page, React Flow draws them, and a test fails if the page is behind the code.

Change workflow graph

The investigator above is one node, investigate, of a second StateGraph (src/cia/workflow.py) that carries a change from request to outcome. It stops twice with interrupt(): for a person's answer, and for the 14-day quiet period. Each wait is checkpointed, so it survives a restart. make graph draws it from the compiled graph too.

Why LangGraph

  • Easy to read. The graph is the design: nodes and routes are named, and the drawing above is generated from the compiled graph, so it can't drift.
  • Explicit routing. Each branch (more tools, submit, retry, cap) is a small routing function with a test, not a jump inside a loop.
  • State and checkpoints. Every step's state is saved under the request id, so a run can be inspected step by step and resumed.
  • Human approval built in. interrupt() pauses the change workflow before the executor and resumes on the human's answer, and again for the 14-day quiet period (PR 3.4, workflow.py). The waits are checkpointed in SQLite now, Postgres later, so they survive a restart.
  • The standard for agentic Python. Reviewers know it; it keeps our own interfaces (LLMClient, EvidenceSource, Pydantic RiskReport). We don't use LangChain models or tools.

What stays in code: LangGraph decides the order; it never decides what is safe. Evidence ids, the step cap, the citation check and "incomplete is never safe" are plain functions in graph.py, each with a unit test.

Guardrails and proof

Every guardrail is code with a test, never an instruction in the prompt.

  • Evidence ids are assigned by codeThe model can only cite ev-deps-3 if a tool returned it in this run.
  • Citation checkUnknown ids drop the finding; a safe_to_delete with any rejection becomes ask_owner. One retry first (Q8).
  • Step cap8 tool calls; hitting the cap returns insufficient_evidence, never a delete.
  • Incomplete is not safeA safe_to_delete stands only if usage, dependencies and tickets were read in full (no unread pages). Otherwise, or when a source fails, it becomes insufficient_evidence. Only safe_to_delete ever permits_delete.
  • Evidence freshnessEach piece of evidence records collected_at and its source_name; source_updated_at only when the source knows it, never invented.
  • Read-only toolsSQLite opened with mode=ro: a write fails in the engine, whatever the prompt says.
  • Lists are paged, never cutThe model sees 50 rows at a time with total and next_offset, and can fetch the rest. A cut list could hide an old "do not remove" ticket.
  • Usage window of at least 90 daysCode clamps the window the model asks for, so a nightly or monthly job can't look dormant.
  • What a verdict may doCode, not the model, turns the verdict into actions: safe_to_delete → disable then delete, disable_first → disable, anything else → nothing. Protected identities allow nothing. A person can approve less, never more (guardrails.py, PR 3.2).
  • Grounded, not just citedValid ids are not enough. A safe_to_delete must agree with the run's own evidence (0 usage, 0 dependencies, no ticket from a person) and cite usage, dependencies and tickets; otherwise code makes it ask_owner and records why in overridden (PR 3.4b).
  • Fresh evidence before actingNo cache. Fresh reads of the five tools are fingerprinted before each investigation and compared again when the person answers and after the quiet period. Unchanged: the same report, no model call. Changed: investigate and ask again. Unreadable: no action. A 7-day backstop on report age (PR 3.4b).
  • Human approval, disable firstNothing runs without a person. The executor dry-runs, disables, waits, and can undo (PR 3.3–3.5). The bench approves everything allowed and still finds 0 wrong deletes (PR 3.6).

Incremental ingestion

  • A cursor per source (position, last success, lag), advanced only after a batch is stored.
  • Overlapping windows (re-read the last few minutes) for late events, with deduplication on a stable event id: the source's own id, or a hash of source, id and timestamp.
  • Documents versioned by content hash; only changed chunks are re-indexed or re-embedded.
  • Retries with backoff; a failing source is recorded and shows up as stale evidence, never as "no rows".
  • Retention and cost: raw logs kept for a fixed window, aggregates longer; logs are never embedded.

How it fits the code

New sources implement the same five methods: an IndexedSource reads the stores above and reports updated_at from its ingestion cursor; a LiveIamSource answers from the IAM API. A destructive verdict would then also need live confirmation of the identity's state and source lag within a limit, or it becomes insufficient_evidence, the rule this week's PR 2.4d starts.
